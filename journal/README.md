# 📓 매매일지

코인 매매를 **혼자** 기록하고, 승률·손익비·기대값을 **자동으로** 계산해주는 1인용 웹 매매일지.
폰·PC 어디서 열어도 같은 데이터를 봅니다. (기록은 Supabase에 저장, 내 계정만 접근)

```
오늘 ─ 빠른 입력 + 오늘 손익/승률 + 오늘 내역
이번 달 ─ 월 손익 + 일별 손익 막대 + 월 내역
전체 ─ 기간·코인·포지션·결과 필터 + 누적 손익 곡선 + 전체 내역
통계 ─ 승률·손익비·기대값·평균익/손·최대낙폭·최대연속패 + 코인별/요일별 성적
복기 ─ 월간 AI 복기 리포트 (반복된 패턴 · 유지할 것 · 다음 달 규칙)
```

## 3분 세팅

### 1) 테이블 만들기
Supabase 대시보드 → **SQL Editor** → [`supabase-setup.sql`](./supabase-setup.sql) 내용을 붙여넣고 **Run**.

> **이미 한 번 실행하셨다면** 다시 실행하세요. 진입가·TP·SL 칸이 나중에 추가됐습니다.
> 없는 칸만 붙이므로 기존 기록은 지워지지 않습니다.
> 그 세 칸만 추가하려면 [`migrations/2026-09-23-add-plan-columns.sql`](./migrations/2026-09-23-add-plan-columns.sql) 만 실행해도 됩니다.

> ⚠️ 앱에서 `Could not find the 'entry_price' column of 'trades' in the schema cache` 오류가 나면
> 그 칸이 아직 없다는 뜻입니다. 위 SQL을 실행하세요. 스크립트 마지막의
> `notify pgrst, 'reload schema';` 가 Supabase에게 새 칸을 알려주는 명령이라 꼭 함께 실행돼야 합니다.

### 2) 내 계정 만들기
Supabase 대시보드 → **Authentication → Users → Add user → Create new user**
- 이메일 / 비밀번호 입력
- **“Auto Confirm User” 체크** ← 이걸 체크해야 메일 인증 없이 바로 로그인됩니다

### 3) 열기

**PC에서 바로** — 저장소 루트에서:
```bash
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000/journal/ 열기
```

**폰에서도 쓰려면 (추천)** — GitHub Pages로 배포:
저장소 → `Settings` → `Pages` → Source: `Deploy from a branch` → 브랜치 선택 → Save
→ `https://<아이디>.github.io/ideal-guide/journal/` 로 접속됩니다.
폰 브라우저에서 열고 **홈 화면에 추가**하면 앱처럼 쓸 수 있습니다.

### 4) 월간 AI 복기 켜기 (선택)

저장소 → `Settings` → `Secrets and variables` → `Actions` → `New repository secret` 로 3개 등록:

| 이름 | 값 |
|---|---|
| `ANTHROPIC_API_KEY` | [console.anthropic.com](https://console.anthropic.com)에서 발급 |
| `JOURNAL_EMAIL` | 위 2)에서 만든 로그인 이메일 |
| `JOURNAL_PASSWORD` | 그 비밀번호 |

실행: GitHub → `Actions` 탭 → **매매일지 월간 복기** → `Run workflow`
(대상 월을 비워두면 지난달, `2026-09`처럼 적으면 그 달)

## 쓰는 법

**기록하기** — 타이핑하는 건 4개뿐입니다.

| 항목 | 설명 |
|---|---|
| 날짜 | 오늘 날짜가 자동으로 채워집니다 |
| 코인 | `BTC`, `ETH` … 자동 대문자. 이전에 쓴 코인은 자동완성됩니다 |
| 포지션 | 롱 / 숏 한 번 탭 |
| 실현 손익 | **청산이 끝난 뒤의 손익.** 손실은 `-`를 붙여 입력 |
| 전략 | 단일 진입 / FVG / 오더블럭 / 기타. **FVG와 오더블럭은 고르면 진입 구간이 3개로 자동 펼쳐집니다** |
| 진입 구간 · TP · SL | **필수.** 거래소 화면의 가격을 그대로 적으면 됩니다. 넣는 즉시 **계획 손익비**가 계산돼 보입니다 |
| 결과 | 기본 **자동** — 손익이 +면 승, 0이면 무, −면 패. 필요하면 직접 지정 |
| 매매 복기 | 분할 매수·매도 내역, 진입 근거, 그때 감정 등 자유롭게 |
| 태그 | 칩을 눌러 선택 (돌파 / FOMO / 손절지연 …) — 나중에 패턴 찾을 때 씁니다 |

**기록 단위는 “포지션 1개 = 1줄”입니다.** 분할로 3번 나눠 사고 2번 나눠 팔았더라도
최종 실현 손익 한 줄로 적고, 분할 내역은 복기란에 적으세요.

**수정·복사·삭제** — 목록의 각 줄 오른쪽에 있습니다.

| 버튼 | 하는 일 |
|---|---|
| `수정` | 그 기록을 폼에 불러와 **덮어씁니다** |
| `복사` | 그 기록의 **코인·포지션·진입가·TP·SL만** 가져와 **새 기록**을 시작합니다 |
| `삭제` | 확인 후 지웁니다 |

**복사**는 같은 자리에 재진입하거나 분할로 나눠 들어갈 때 씁니다.
날짜는 오늘로 바뀌고, **실현 손익·복기·태그는 비워집니다** — 그 매매에만 해당하는 내용이라서입니다.
원본은 그대로 남고, 저장하면 새 줄이 하나 생깁니다.

**통화 전환** — 우측 상단에서 `USDT` ↔ `원화`. 표시 형식만 바뀝니다(환산 아님).

**백업** — 화면 맨 아래 `⬇ CSV 내보내기`. 엑셀에서 바로 열리고, 한글이 깨지지 않습니다.

## 계획 손익비 (R)

진입 전에 정한 **진입가 · TP · SL**로 계산합니다.

```
롱  →  계획 R = (TP − 진입가) ÷ (진입가 − SL)
숏  →  계획 R = (진입가 − TP) ÷ (SL − 진입가)
```

예: 진입 67,200 / TP 69,000 / SL 66,300 → 목표폭 1,800 ÷ 손절폭 900 = **2.00R**

입력칸에 숫자를 넣는 **즉시** 아래에 뜹니다. 기록을 남기기 전에 "이 매매가 걸 만한가"를 눈으로 확인하라고 만든 자리입니다.

**막아둔 것**
- 셋 중 하나라도 비면 저장되지 않습니다.
- 롱인데 TP가 진입가보다 낮거나, 숏인데 SL이 진입가보다 낮으면 저장되지 않습니다. (거의 항상 오타입니다)
- 1R 미만이면 "손절폭이 목표폭보다 큽니다"라고 알려줍니다. 막지는 않습니다 — 그런 매매를 하고 있다는 사실 자체가 기록될 값어치가 있습니다.

## 분할 진입 (FVG · 오더블럭)

**FVG와 오더블럭**은 한 자리를 나눠 들어가는 전략이라, 전략에서 고르면 **진입 구간이 바로 3개로 펼쳐집니다.**
`+ 구간 추가`로 더 늘릴 수 있고(최대 5개), `×`로 줄일 수 있습니다. **TP와 SL은 구간 전체가 공유합니다.**

`단일 진입`으로 되돌리면 **값이 비어 있는 구간만** 접힙니다 — 적어둔 가격은 지우지 않습니다.

### 비중은 기본으로 뒤쪽에 더 실립니다

비워두면 **마지막(가장 깊은) 구간에 절반**, 나머지가 나머지 절반을 나눠 갖습니다.

| 칸 수 | 기본 비중 |
|---|---|
| 3칸 | **25% · 25% · 50%** |
| 2칸 | **50% · 50%** |
| 4칸 | 16.7% · 16.7% · 16.7% · 50% |
| 1칸 | 100% |

**칸을 지우면 남은 칸 수에 맞춰 자동으로 다시 나뉩니다.** 3칸에서 하나 지우면 바로 50/50이 됩니다.

직접 정하고 싶으면 비중 칸에 숫자를 적으세요. **비율로 읽습니다** — `1 / 1 / 2`도 `25 / 25 / 50`과 같습니다.
어느 쪽이든 **실제로 적용된 비율이 각 칸 옆에 바로 표시**되니 헷갈릴 일은 없습니다.

```
평균 진입가 = Σ (구간 가격 × 그 구간의 비중)
```

이 **가중평균 진입가**가 곧 포지션의 진입가입니다.
`총 위험 = 총 수량 × |평균 진입가 − SL|` 이 정확히 성립하기 때문에,
손익비·수량·증거금이 단일 진입과 똑같은 식으로 계산됩니다.

예 — FVG 롱, 100 / 98 / 96에 `1:1:2`로, TP 120 · SL 94, 계좌 10,000 · 최대 손실률 1%

| | |
|---|---|
| 평균 진입가 | **97.5** |
| 계획 손익비 | **6.43R** |
| 총 수량 | 28.5714 BTC |
| 구간별 수량 | ① 7.1429 · ② 7.1429 · ③ 14.2857 |
| 익절 / 손절 | **+$642.86** / **−$100.00** |

깊은 구간에 더 실으면 평균가가 낮아져 손익비가 올라갑니다 (균등 분배면 5.50R, `1:1:2`면 6.43R).
대신 얕은 구간만 체결되고 돌아설 위험은 커집니다 — 그 판단은 직접 하세요.

**구간 하나라도 손절가 반대편에 있으면 저장되지 않습니다.** (롱인데 SL보다 낮은 구간 등)

> 어느 구간이 실제로 체결됐는지는 복기란에 적어두세요.
> 기록되는 건 **계획**이고, 실제 결과는 실현 손익 한 줄로 들어갑니다.

`통계` 탭에 **전략별 성적**(건수·승률·평균 계획 R·누적 손익)이 나오고,
월간 AI 복기도 어느 전략이 실제로 돈을 벌고 있는지 짚습니다.

## 진입 비중 (포지션 사이징)

**"이번 매매에 얼마를 걸어야 하나"** 를 감이 아니라 계산으로 정합니다.

진입가·TP·SL을 넣으면 **손절 퍼센트**가 나오고, 여기에 **계좌**와 **최대 손실률**을 넣으면 진입 비중이 계산됩니다.

```
손절 %    = (진입가 − SL) ÷ 진입가 × 100
진입 비중 = 계좌 × 최대 손실률 ÷ 손절 %      ← 포지션 전체 크기
수량      = 진입 비중 ÷ 진입가
증거금    = 진입 비중 ÷ 레버리지             ← 거래소에 실제로 넣는 돈
```

예: 진입 72.43465 / SL 70.19 → 손절 **3.10%**
계좌 10,000 USDT · 최대 손실률 **1%** (= 한 번에 100 USDT까지만 잃겠다)
→ 진입 비중 **$3,226.99** ≈ **44.55개**

여기에 **레버리지 10배**면 → **증거금 $322.70**. 이게 거래소에 실제로 넣는 돈입니다.

이렇게 넣으면 손절에 걸려도 **정확히 100 USDT만** 잃습니다.
손절폭이 넓은 자리는 적게, 좁은 자리는 크게 — 자동으로 조절됩니다.

### 거래소에 주문할 때 쓰는 숫자

| 화면 | 뜻 |
|---|---|
| **증거금** | 실제로 넣는 돈. 레버리지를 바꾸면 이 숫자만 바뀝니다 |
| **수량** | 주문 수량. 레버리지와 무관하게 항상 같습니다 |
| 진입 비중 | 포지션 전체 크기 (증거금 × 레버리지) |
| 익절하면 / 손절하면 | TP·SL에 닿았을 때의 금액. **레버리지를 올려도 이 두 금액은 안 바뀝니다** |

맨 아랫줄이 이 매매의 전부입니다 — **익절하면 얼마를 벌고, 손절하면 얼마를 잃는가.**
손절 금액은 항상 `계좌 × 최대 손실률`로 고정되고, 익절 금액은 `손절 금액 × 계획 손익비`입니다.
그래서 **손익비가 1보다 작으면 이기고도 지는 쪽보다 적게 법니다.**

예: 진입 84,450 / TP 85,450 / SL 81,878 → 0.39R
→ `익절하면 +$264.39 · 손절하면 −$680.00`
맞혀도 264 벌고 틀리면 680 잃는 자리입니다. 숫자로 보면 안 들어가게 됩니다.

> 레버리지를 올린다고 위험이 커지지 않습니다. 수량이 그대로이기 때문입니다.
> 레버리지는 **증거금을 얼마나 묶어둘지**만 정합니다. 위험을 정하는 건 손절가와 최대 손실률입니다.

- **계좌 · 최대 손실률 · 레버리지는 기억됩니다.** 한 번 넣으면 다음부터 자동으로 채워집니다. (이 브라우저에만 저장되며 매매 기록에는 남지 않습니다)
- **증거금이 계좌보다 크면** 필요한 최소 레버리지를 알려줍니다.
- 계좌·최대 손실률을 비워두면 손절 퍼센트까지만 나옵니다. **필수가 아닙니다.**

### 계획 vs 실제 — 이게 핵심입니다

`통계` 탭에 두 숫자가 나란히 나옵니다.

| | 뜻 |
|---|---|
| **계획 손익비** | 진입 전에 내가 정한 비율의 평균 |
| **실제 손익비** | 실제로 번 돈과 잃은 돈의 비율 (평균수익 ÷ 평균손실) |

**계획 2.4R인데 실제가 0.9라면** 방향은 맞혔는데 계획대로 실행하지 못했다는 뜻입니다.
이익은 목표가 전에 일찍 확정하고, 손실은 손절가를 넘겨 버티고 있을 가능성이 큽니다.
승률로는 절대 안 보이는 문제이고, 월간 AI 복기도 이 격차를 우선해서 짚습니다.

## 월간 AI 복기

한 달치 기록 전체(손익·태그·복기란에 적은 내 말)를 읽고 **반복되는 행동 패턴**을 찾아냅니다.

나오는 것:
- **반복된 패턴** — 패턴 이름 + 기록 속 근거(날짜·코인·태그) + 그게 실제로 잃게 한 금액 + 바꿀 행동
- **계획과 실제의 격차** — 계획 손익비와 실제 손익비가 벌어진 매매를 날짜·코인으로 지목
- **유지할 것** — 잘하고 있는 습관
- **다음 달 규칙** — 지켰는지 판정 가능한 문장으로
- **질문 하나** — 스스로 답해볼 것

안 하는 것: 시장 전망, 종목 추천, 위로. 내 기록에 없는 숫자는 쓰지 않습니다.

**실행** — GitHub `Actions` 탭 → `매매일지 월간 복기` → `Run workflow`.
결과는 앱의 **[복기] 탭**에 바로 뜹니다. 같은 달을 다시 돌리면 덮어씁니다.

매월 1일 자동 실행을 켜려면 `.github/workflows/journal-report.yml`의 `schedule` 3줄 주석을 푸세요.
(한 달에 API 호출 1회라 비용은 매우 작습니다)

```bash
# 로컬에서 돌려보려면 (.env 에 ANTHROPIC_API_KEY / JOURNAL_EMAIL / JOURNAL_PASSWORD 필요)
npm run journal:report              # 지난달
npm run journal:report 2026-09      # 특정 월
node src/journal-report.js --dry-run  # AI 호출 없이 집계만 확인
```

> **리포트는 저장소가 아니라 Supabase에 저장됩니다.** 저장소가 공개일 수 있어서,
> 매매 금액이 파일이나 Actions 로그에 남지 않도록 일부러 그렇게 했습니다.
> 실행 로그에는 "매매 23건, 패턴 3개" 같은 건수만 찍힙니다.

| 지표 | 뜻 | 봐야 하는 이유 |
|---|---|---|
| 승률 | 승 ÷ (승 + 패) | 높다고 좋은 게 아닙니다. 아래 둘과 같이 봐야 합니다 |
| **손익비** | 평균 수익 ÷ 평균 손실 | **1보다 작으면** 이길 때 조금 벌고 질 때 크게 잃는 중 |
| **1회 기대값** | (승률 × 평균수익) − (패율 × 평균손실) | **음수면 매매를 할수록 계좌가 줄어듭니다.** 가장 중요한 숫자 |
| 최대 낙폭 | 누적 고점 대비 최대 하락폭 | 내가 실제로 견뎌야 했던 최악의 구간 |
| 최대 연속 패 | 연속으로 진 최대 횟수 | 손실 후 뇌동매매 구간을 찾는 단서 |

> 승률 70%인데 기대값이 음수인 경우가 흔합니다. 승률만 보면 그게 안 보입니다.

**색 규칙**: 수익 = 빨강, 손실 = 파랑 (국내 차트 관례).
색맹 사용자도 구분되도록 색 대비를 검증했고, 결과는 색과 함께 `승`/`무`/`패` 글자로도 표시됩니다.

## 파일

```
journal/
  index.html          화면 구조
  app.js              로직 (집계·차트·CRUD·CSV·복기 표시)
  styles.css          스타일 (라이트/다크 자동)
  supabase-setup.sql  테이블 2개(trades, journal_reports) + 보안 정책
src/
  journal-report.js   월간 AI 복기 생성
.github/workflows/
  journal-report.yml  복기 실행 버튼
```

설정은 저장소 루트의 `config.js`(Supabase 주소·공개키)를 그대로 씁니다.

## 보안

`trades`와 `journal_reports` 테이블은 **RLS(행 수준 보안)** 로 잠겨 있어 로그인한 본인 행만 읽기·쓰기·삭제됩니다.
루트의 방명록(`messages`)과 달리 “누구나 읽기/쓰기”가 아닙니다.
`config.js`의 키는 브라우저에 노출되도록 설계된 **공개용 키**라 공개 저장소에 있어도 안전합니다.
(SECRET 키는 절대 프론트엔드에 넣지 마세요.)
