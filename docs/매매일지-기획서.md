# 📓 매매일지 (Trading Journal) — 기획서 v1

> 한 줄 정의: **나 혼자 쓰는, 매매 1건을 10초 안에 기록하고 승률·손익을 자동으로 계산해주는 개인용 웹 매매일지.**

---

## 1. 왜 만드나 (현재 노션 표의 문제)

현재 노션 구조: `오늘 매매 내역` / `이번 달 매매 내역` / `총 매매 내역` / `오늘 총 수익금(도넛)`
컬럼: 날짜 · 종목명 · 포지션 · 승 · 무 · 패 · 수익금 · 매매 복기

| 불편한 점 | 프로그램에서 해결 |
|---|---|
| 승·무·패를 체크박스 3개로 **수동** 선택 | 수익금만 넣으면 **자동 판정** (+면 승, 0이면 무, −면 패) |
| 오늘/이번 달/전체를 **표 3개**로 따로 관리 | 테이블 1개 + **탭 전환**만 (필터 자동) |
| 승률·손익비·기대값을 직접 계산해야 함 | **자동 집계 카드**로 항상 표시 |
| 모바일에서 표 입력이 느림 | 폰 최적화된 **한 화면 입력 폼** |
| 복기 글이 쌓이기만 하고 분석이 안 됨 | 태그 + 월간 리포트로 **패턴 도출** |

**핵심 목표 = 입력은 최소로, 계산은 전부 자동으로.**

---

## 2. 사용자와 설계 원칙

- 사용자: **1명(나)**. 공유·협업 기능 없음. 로그인 1계정.
- 원칙 3가지
  1. **입력 필드는 5개 이하** — 귀찮으면 안 쓰게 된다.
  2. **계산은 사람이 안 한다** — 승률·합계·연속패 전부 자동.
  3. **데이터는 내 것** — 언제든 CSV로 내보내고 되돌릴 수 있다.

---

## 3. 데이터 모델 — 테이블 1개면 끝

`trades` (매매 1건 = 1행, **청산 완료 기준**)

| 컬럼 | 타입 | 필수 | 설명 |
|---|---|:--:|---|
| `id` | bigint | ✅ | PK (자동) |
| `user_id` | uuid | ✅ | 내 계정 (RLS용, 자동) |
| `traded_at` | date | ✅ | 매매 날짜 (기본값 = 오늘) |
| `symbol` | text | ✅ | 종목명 (예: 삼성전자, BTC) |
| `position` | text | ✅ | `long`(롱/매수) \| `short`(숏/매도) |
| `pnl` | numeric | ✅ | 수익금 (손실은 음수) |
| `result` | text | ✅ | `win` \| `draw` \| `lose` — **pnl로 자동 계산, 수정 가능** |
| `memo` | text | | 매매 복기 (자유 서술) |
| `tags` | text[] | | 복기 태그 (예: `돌파`, `FOMO`, `계획대로`) |
| `created_at` | timestamptz | ✅ | 기록 시각 (자동) |

**입력 시 실제로 타이핑하는 건 4개뿐**: 종목명 · 포지션 · 수익금 · (선택)복기
날짜는 오늘로 자동, 승패는 수익금에서 자동.

### 나중에 붙일 선택 컬럼 (Phase 2, 지금은 넣지 않음)
`entry_price`(진입가) · `exit_price`(청산가) · `qty`(수량) · `strategy`(전략명) · `screenshot_url`(차트 캡처)

│  +182,000원    2승 1패     3건                │

│ 09-21  삼성전자  롱    ✅승  +120,000 계획대로 │

| 탭 | 보여주는 것 |
|---|---|
| **오늘** | 빠른 입력 폼 + 오늘 손익/승률 카드 + 오늘 목록 |
| **이번 달** | 월 누적 손익 + 일별 손익 막대그래프 + 월 목록 |
| **전체** | 기간·종목·포지션·결과 필터 + 전체 목록 + 누적 손익 곡선 |
| **통계** | 아래 8개 지표 + 종목별·요일별·태그별 성적 |

## 5. 자동 계산 지표 (직접 계산할 필요 없는 것들)

| 지표 | 계산식 |
|---|---|
| 총 손익 | Σ pnl |
| 승률 | 승 ÷ (승 + 패) |
| 평균 수익 | 이익 거래 pnl 평균 |
| 평균 손실 | 손실 거래 pnl 평균(절댓값) |
| **손익비** | 평균 수익 ÷ 평균 손실 |
| **기대값** | (승률 × 평균수익) − (패율 × 평균손실) — *1회 매매당 기대 금액* |
| 최대 연속 패 | 연속 `lose` 최대 길이 |
| 최대 낙폭(MDD) | 누적 손익 곡선의 고점 대비 최대 하락폭 |

> 손익비와 기대값이 이 프로그램의 진짜 가치입니다. 승률 70%여도 기대값이 음수면 계좌는 녹습니다.

## 7. 기술 스택 — 추천안

**추천: 지금 저장소 스택 그대로 (정적 HTML/CSS/Vanilla JS + Supabase + GitHub Pages)**

이유 3가지:
1. `index.html` + `app.js` + `styles.css` + `supabase-setup.sql` 구조가 이미 돌아가고 있음 → **새로 배울 것 0**
2. 폰·PC 어디서든 같은 데이터 (Supabase Postgres에 저장)
3. **비용 0원** (Supabase 무료 티어 + GitHub Pages 무료)

| 대안 | 장점 | 단점 | 판단 |
|---|---|---|---|
| 완전 로컬 (localStorage만) | 서버·로그인 불필요, 가장 단순 | 폰↔PC 동기화 안 됨, 브라우저 정리하면 **데이터 날아감** | ❌ 기록용으론 위험 |
| Next.js + Vercel | 확장성 좋음 | 1인용 기록 앱엔 과함, 빌드 학습 필요 | ❌ 과설계 |
| **정적 + Supabase** | 위 3가지 | 초기 로그인 세팅 10분 | ✅ **채택** |

## 8. 보안 — 방명록 정책을 그대로 쓰면 안 됩니다 ⚠️

현재 `supabase-setup.sql`은 **"누구나 읽기 / 누구나 쓰기"** 정책입니다. 방명록은 그게 맞지만, 매매일지는 내 손익이 그대로 노출되고 누구나 지울 수 있게 됩니다.

→ **Supabase Auth 이메일 로그인 1계정 + RLS `user_id = auth.uid()`** 로 잠급니다. (내 행만 읽기·쓰기·삭제 가능)

### SQL 스키마 초안

```sql
create table if not exists public.trades (
  id         bigint generated always as identity primary key,
  user_id    uuid not null default auth.uid() references auth.users(id) on delete cascade,
  traded_at  date not null default current_date,
  symbol     text not null,
  position   text not null check (position in ('long','short')),
  pnl        numeric(14,2) not null default 0,
  result     text not null check (result in ('win','draw','lose')),
  memo       text,
  tags       text[] not null default '{}',
  created_at timestamptz not null default now()
);

create index if not exists trades_user_date_idx on public.trades (user_id, traded_at desc);

alter table public.trades enable row level security;

create policy "내 기록만 조회" on public.trades
  for select to authenticated using (auth.uid() = user_id);
create policy "내 기록만 추가" on public.trades
  for insert to authenticated with check (auth.uid() = user_id);
create policy "내 기록만 수정" on public.trades
  for update to authenticated using (auth.uid() = user_id);
create policy "내 기록만 삭제" on public.trades
  for delete to authenticated using (auth.uid() = user_id);
```

### 백업
주 1회 CSV 내보내기(P2) 또는 Supabase 대시보드에서 테이블 다운로드. 무료 티어는 **일정 기간 접속이 없으면 프로젝트가 일시 중지**될 수 있으므로 CSV 백업을 습관화합니다.

## 9. 확정이 필요한 3가지

1. **자산군과 통화** — 국내 주식(원) / 해외 주식(달러) / 코인(USDT) 중 무엇인가요? 수익금 단위와 표시 형식이 달라집니다. (기본값: **원화**)
2. **폰에서도 쓸 건가요?** — 예 → Supabase(추천안 그대로) / 아니요, PC만 → 로그인 없이 로컬 저장으로 더 단순하게 갈 수도 있습니다.
3. **기록 단위** — "1건 = 청산 완료된 매매 1개"로 잡았습니다. 분할 매수·매도를 여러 줄로 쪼개 적고 싶다면 진입가·수량 컬럼을 P0부터 넣어야 합니다. (기본값: **청산 1건 = 1줄**)
